# DefenderPilot

Русская программа для управления и восстановления Microsoft Defender в **Windows 10/11 x64**.

## Возможности

| Кнопка | Действие |
|---|---|
| Включить защиту | Запускает WinDefend, если это разрешено, включает защиту в реальном времени, поведенческий анализ, проверку загрузок и скриптов |
| Временно отключить | Запрашивает отключение защиты в реальном времени через `Set-MpPreference` и проверяет фактическое состояние |
| Восстановить компоненты | Последовательно запускает `DISM /Online /Cleanup-Image /RestoreHealth /NoRestart`, `sfc /scannow` и включение Defender |
| Обновить базы | Запускает `Update-MpSignature` |
| Обновить состояние | Показывает защиту, антивирус, службу, защиту от подделки, версию баз и режим работы |
| Безопасность Windows | Открывает штатную страницу управления защитой |

Все изменения запускаются пользователем из окна. Состояние автоматически обновляется каждые 30 секунд. Неизвестное состояние отображается как «Неизвестно», а отказ Windows — в журнале. Изменение параметра не считается успешным, пока Windows не подтвердила фактическое состояние защиты.

## Запуск EXE

1. Откройте **Releases** этого репозитория.
2. Скачайте `DefenderPilot.exe` и запустите.
3. Подтвердите запрос прав администратора Windows.

Программа переносимая, Python пользователю не нужен. EXE не подписан сертификатом издателя. Контрольная сумма публикуется рядом в `SHA256SUMS.txt`.

## Ограничения восстановления и отключения

- Отключается защита **в реальном времени**, а не весь защитный стек. Windows может автоматически включить её снова, в том числе после перезагрузки.
- При включённой **защите от подделки** программа сообщает о блокировке. Настройка доступна вручную: «Безопасность Windows» → «Защита от вирусов и угроз» → «Управление настройками». После диагностики верните защиту от подделки во включённое состояние.
- Политики организации и сторонний антивирус могут запрещать включение или отключение. Программа показывает отказ и не удаляет политики.
- DISM/SFC восстанавливают компоненты Windows. Если Defender вырезан из модифицированной системы, его полное возвращение не гарантируется: может понадобиться восстановительная установка официального Windows с сохранением приложений и файлов.
- DISM может потребовать интернет и источник компонентов. Восстановление иногда занимает более часа. Программа не перезагружает компьютер автоматически.
- Программа не меняет исключения, брандмауэр и облачные настройки, не удаляет службы или файлы Defender и не добавляет задачи автозапуска.

## Журнал

Файлы: `%LOCALAPPDATA%\DefenderPilot\logs\defenderpilot.log` (ротация: до четырёх файлов по 2 МБ). Вывод можно скопировать кнопкой в окне.

Если восстановление сообщает об ошибках, проверьте также `%WINDIR%\Logs\DISM\dism.log` и `%WINDIR%\Logs\CBS\CBS.log`.

## Запуск из исходников

Нужен Python 3.12 x64 с Tkinter и Windows PowerShell 5.1, входящий в Windows. Сторонние библиотеки для запуска не нужны.

```powershell
python app.py
```

Программа сама запрашивает права администратора. PowerShell запускается с политикой `RemoteSigned` только для дочернего процесса. Если скачанные исходники помечены Windows как полученные из интернета, снимите блокировку ZIP в его свойствах перед распаковкой, предварительно проверив источник.

## Сборка

```powershell
.\build.ps1
```

Результат: `dist\DefenderPilot.exe`. Используется PyInstaller 6.16.0; манифест EXE запрашивает права администратора.

## Автоматические Releases

GitHub Actions при push в `main` проверяет PowerShell, запускает тесты с имитацией Defender, собирает EXE на Windows, проверяет включение скрипта в пакет и публикует первый Release `v1.0.0` с EXE и SHA-256. Тесты не меняют защиту на машине сборки.

Для следующего релиза увеличьте `__version__` в `defenderpilot/__init__.py` и обновите `RELEASE_NOTES.md`. Существующие Releases не перезаписываются. Сборка также запускается вручную через Actions → Test, build and release → Run workflow.

## Проверка

```powershell
$env:DEFENDERPILOT_GUI_TEST = '1'
python -m unittest discover -s tests -v
```

Тесты проверяют обработку ошибок/ответов, неизвестные состояния и интерфейс с имитацией backend. Реальное восстановление и переключение Defender следует проверять в Windows на тестовой виртуальной машине; эти проверки не выполняются автоматически.
